# 运行与答辩说明

## 一、推荐运行环境

- Windows 10/11
- JDK 17
- Maven 3.9+
- Node.js 20+
- Docker Desktop 4+

## 二、Docker一键启动

在项目根目录打开终端：

```bash
cd docker
docker compose up -d --build
```

第一次启动需要下载镜像和Maven、npm依赖，因此用时会较长。启动完成后访问：

- 系统页面：`http://localhost:8088`
- 后端网关：`http://localhost:8080`
- Nacos：`http://localhost:8848/nacos`
- MySQL：`localhost:3307`

关闭系统：

```bash
docker compose down
```

查看服务状态：

```bash
docker compose ps
```

查看某个服务日志：

```bash
docker compose logs -f gateway
```

## 四、非Docker运行

1. 在MySQL中执行 `sql/library_all.sql`。
2. 将各服务 `application.yml` 中的MySQL密码改成自己的密码。
3. 启动Nacos。
4. 在项目根目录执行：

```bash
mvn clean package -DskipTests
```

5. 依次启动认证、图书、读者、流通、系统、统计和网关服务。
6. 启动前端：

```bash
cd library-web
npm install
npm run dev
```

访问 `http://localhost:5173`。

## 六、核心答辩问题

### 1. 为什么使用微服务？

系统的认证、图书、读者、借阅和统计职责不同。拆分后，各模块可以独立开发、启动和扩容；某个非核心服务暂时出现问题时，不需要停止整个系统。但微服务也会增加部署和通信复杂度，所以本项目只拆分边界清晰的核心业务。

### 2. 网关有什么作用？

前端只需要访问8080端口。网关统一完成JWT校验、跨域处理和服务路由，避免每个服务重复编写相同逻辑，也避免前端记住每个微服务的端口。

### 3. 项目中的多表查询在哪里？

借阅记录查询同时连接借阅记录、图书、馆藏副本、读者和用户五张表，因此页面可以一次显示书名、馆藏条码、读者编号和读者姓名。图书查询还连接分类和出版社表。

### 4. 如何防止一本馆藏被两个人同时借走？

借书操作在事务中使用 `FOR UPDATE` 锁定可借馆藏记录。第一个事务锁定后，第二个事务不能同时把同一副本借走。借阅记录、馆藏状态和可借数量要么全部成功，要么全部回滚。

### 5. Docker解决了什么问题？

Docker把JDK、Nginx、MySQL、Nacos以及项目服务运行环境封装起来，避免不同电脑上版本和配置不一致。Docker Compose则负责按照统一配置启动全部容器。

## 七、提交压缩包说明

提交时不要加入以下目录：

```text
node_modules
target
dist
.idea
.vscode
```

这些都是依赖或构建产物，不属于源码，而且会让压缩包超过50MB。
